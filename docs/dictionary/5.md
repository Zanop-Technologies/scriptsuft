# Entry 5: Syntax Errors and Diagnostics

When code does not follow Scriptsuft's expected patterns, the runtime now reports clear syntax errors with line numbers so you can fix issues quickly.

## How errors are reported

- The interpreter stops on the first syntax error it finds.
- Error messages include the line number and a short explanation.
- Common errors reported include: missing colons/braces after `if`/`while`, unclosed indented blocks, and unsupported statements.

## Example: missing colon

Bad:

```text
if age is 18
    speak("Missing colon or brace")
```

Interpreter output:

```
SyntaxError: Unsupported if statement at line 2: if age is 18
```

Fix by adding `:` or a `{` after the condition:

```text
if age is 18:
    speak("Fixed")
```

## Example: unclosed block

If an indented block is started but the file ends (or next line dedents) without closing the block, the runtime reports the starting line:

```
SyntaxError: Unclosed block starting at line 10
```

## Tips

- Use consistent indentation for blocks (examples use 2 spaces or 4 spaces).
- Place `loop-limit(n)` before `while` loops when testing complex logic to avoid runaway loops.
- If you want more diagnostics (column numbers, suggestions), that can be added next.
