# Entry 6: Linking Files

This page explains how Scriptsuft links files, identifiers, and references together. This is the part where one thing points to another, so the app knows what file or resource it should use.

## Link the identifier

The docs sometimes use this pattern:

```text
class var ('compile'):
  if compile = __gets__ from main:
    link the identifier ".identify/"
```

This means:
- `compile` is the task or class doing compilation
- `__gets__ from main` means it pulls data from `main`
- `link the identifier` tells Scriptsuft to connect to the specified path or resource

## Why linking matters

Linking is how one part of the language points to another part of the project. Without a link, the app may know a name but not know where it belongs.

Example:

```text
link the identifier ".identify/"
```

This is basically saying: "use this identifier path as the linked resource." It tells the compiler or runtime to follow that reference.

## Basic rule

When you see:

```text
link the identifier "..."
```

think:

- take this identifier
- connect it to the path or file named inside the quotes
- use it as the reference for the current script or class

## Real-world example

```text
class var ('compile'):
  if compile = __gets__ from main:
    link the identifier ".identify/"
    compile()
```

This is saying: "When the compile task gets data from main, link the identifier path and then run the compile routine."

## Summary

Linking is the part of Scriptsuft where the code says: "this object belongs with this file, path, or resource." So whenever you see `link the identifier`, remember:
- it connects a symbol to a resource
- it is part of app wiring
- it helps the language find the correct file or class reference
